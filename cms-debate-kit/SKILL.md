# CMS Debate Kit

도서 발췌문을 유일한 내용 근거로 삼아 `발췌문 → 논제 → 근거카드 → 활동지·루브릭 → 인용 검증` 순서의 토론 수업 자료를 만든다. 사용자가 일부 단계만 요청하면 필요한 단계만 수행하되, 아래 근거·보존·저장 규칙은 항상 적용한다.

## 시작 전

1. 대상 폴더와 발췌문, 토론 규칙, 기존 양식 등 입력 자료를 읽기 전용으로 확인한다.
2. 파일을 만들거나 바꾸기 전에 작업 범위, 입력 파일, 생성할 산출물, 예상 결과와 저장 예정 절대 경로를 사용자에게 먼저 제시한다.
3. 사용자의 명시적 승인을 받은 범위와 파일에 한해서만 생성·수정한다. 추가 작업은 다시 승인받는다.
4. 자료가 불완전하거나 판본·문단 번호가 불명확하면 해당 사실을 `확인 필요`로 표시한다.

## 절대 규칙

- 발췌문에 없는 사실, 해석, 배경지식, 인터넷 자료를 토론 근거로 제시하지 않는다.
- 발췌문만으로 판단할 수 없는 주장이나 질문에는 정확히 `발췌문에서 확인 불가`라고 표시한다.
- 직접 인용은 발췌문의 문구를 원문 그대로 옮기고 문단 번호를 함께 적는다. 맞춤법, 띄어쓰기, 문장부호를 임의로 고치거나 생략·의역하지 않는다.
- 원문 일부를 줄여 인용해야 한다면 생략 표시를 사용하되 의미를 바꾸지 않으며, 가능하면 전체 문장을 우선한다.
- 발췌문, 토론 규칙, 양식 등 모든 원본 파일은 수정·이동·삭제하거나 파일명을 변경하지 않는다.
- 새 문서, 코드, 표, 리포트 등 모든 산출물은 대상 작업 폴더 바로 아래의 `결과물` 폴더에 저장한다. `결과물` 폴더 생성도 사전 계획과 승인 범위에 포함한다.
- 기존 결과물과 이름이 충돌하면 덮어쓰지 말고 새 파일명을 계획하여 다시 알린다.

## 워크플로우

### 1. 발췌문 정리

- 문단 경계를 보존하고 문단 번호를 확인한다.
- 등장인물의 발언, 사건, 선택, 갈등, 가치 판단을 발췌문에서 직접 확인되는 범위로만 정리한다.
- OCR 오류, 누락, 판독 불가 부분은 추측해 복원하지 않고 `확인 필요`로 표시한다.

### 2. 논제 만들기

- 찬반 양측이 발췌문 안의 근거로 논증할 수 있는 논제를 만든다.
- 외부 지식이 있어야 답할 수 있거나 한쪽 입장이 발췌문에서 성립하지 않는 논제는 피한다.
- 각 논제에 관련 문단 번호와 발췌문 내 쟁점을 연결한다.

### 3. 근거카드 만들기

- 찬성·반대 또는 관점별로 주장을 구분한다.
- 각 카드에는 `주장`, `원문 인용`, `문단 번호`, `인용이 주장을 뒷받침하는 이유`, `한계 또는 반론`을 포함한다.
- 이유와 한계도 발췌문에서 확인되는 범위를 넘지 않는다. 근거가 부족하면 `발췌문에서 확인 불가`로 표시한다.

### 4. 활동지와 루브릭 만들기

- 활동지는 논제 이해, 근거 선택, 주장 구성, 반론·재반론, 성찰을 기록할 수 있게 구성한다.
- 루브릭은 최소한 발췌문 근거 사용, 인용 정확성, 문단 번호 표기, 주장과 근거의 연결, 반론 대응을 평가한다.
- `발췌문에서 확인 불가`를 정직하게 표시한 경우를 근거 조작이나 무근거 추론보다 불리하게 평가하지 않는다.
- 사용자가 제공한 양식이 있으면 원본을 보존하고 결과물 사본에만 적용한다.

### 5. 인용 검증

완성된 모든 논제, 근거카드, 활동지 예시, 루브릭 설명을 다시 검사한다.

- 인용문이 발췌문과 글자 단위로 일치하는지 확인한다.
- 문단 번호가 실제 위치와 일치하는지 확인한다.
- 인용 앞뒤의 설명이 원문보다 강한 주장으로 확대되지 않았는지 확인한다.
- 발췌문 밖 사실이나 출처가 섞이지 않았는지 확인한다.
- 확인 실패 항목은 고쳐 쓰거나 `발췌문에서 확인 불가` 또는 `확인 필요`로 표시한다.

## 완료 보고

작업 후 생성하거나 변경한 파일과 검수할 항목을 표로 정리한다. 파일 수, 각 파일의 역할, 최종 절대 경로, 인용 검증 결과를 함께 보고한다. 원본이 변경되지 않았음도 명시한다.
